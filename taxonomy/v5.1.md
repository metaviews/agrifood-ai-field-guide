# Taxonomy — v5.1 errata (conventions and normalization)

**Status.** Errata release on top of v5 (`taxonomy/v5.md`, unchanged and authoritative for the three primary axes, the eleven original cross-cutting tags, and the four maturity dimensions). v5.1 adds no tags and removes none; it records the conventions the corpus had already developed in practice, fixes the vocabulary drift those conventions left behind, and normalizes the affected frontmatter. Released 15 November 2026 alongside a corpus-wide audit. Superseded structurally by v6 (unit-kind, governance-level, axis extensions) the same day; retained as the normalization record.

**Why an errata rather than a version.** The audit found drift, not disagreement: no unit's meaning changes under these rules, and every normalization below is a prefix-level rewrite that preserves the unit's own detail text. A version bump would have implied re-litigating v5's structure, which the audit found sound for what it covers.

---

## 1. Region: canonical grammar and prefix list

**Grammar.** `region: PREFIX (free-text detail)` — the leading token of the value is a controlled prefix; everything in parentheses (and any trailing clauses) is free text preserved from the unit's own framing. Multi-region units use comma- or semicolon-separated segment lists, each segment following the same grammar. Non-geographic units (frameworks, methodologies, critical analyses) use the recognized form `(cross-cutting — reason)`.

**Controlled prefix list** (extends v5's enum with the values practice had already forced):

| Prefix | Covers |
|---|---|
| NA-US | United States (v5's NA-US; the NA-USA variant is retired) |
| NA-Canada | Canada, including provincial detail |
| LATAM | Latin America, Caribbean, and Mexico (retires the in-practice South-America / North-America(Mexico) / Central-America variants) |
| EU | EU-wide and supranational EU instruments (new; v5 had only member-state prefixes) |
| EU-<member state> | EU-Netherlands, EU-France, EU-Germany, EU-Spain, EU-other (EU-Spain new — the Spain cycle made bare "Spain" the fourth member-state value in practice) |
| MENA | Middle East and North Africa (new; retires the in-practice Middle-East / bare Morocco / bare Tunisia forms) |
| SSA | Sub-Saharan Africa (retires spelled-out "Sub-Saharan Africa (…)" values) |
| South-Asia | India and South Asia |
| East-Asia | China, Japan, Korea (retires the NA-Asia typo) |
| Oceania | Australia, Aotearoa NZ |
| Global | worldwide scope (retires lowercase "(global…)" and "international (…)") |
| Global-South | the Mozilla/archetype-07 sense: Global South as an analytic region, not a sum of continents |
| multi-region | explicit multi-region lists that do not reduce to one prefix (e.g. Belt-and-Road partner states) |

**Normalizations applied 2026-11-15** (prefix-level only; detail text preserved in every case; 81 units touched in total, zero meaning changes — the per-file mapping is the commit diff): NA-USA → NA-US; South-America / North-America(Mexico) / Central-America → LATAM; Middle-East / bare Morocco / bare Tunisia → MENA; Europe ( → EU (; bare Spain → EU-Spain; Sub-Saharan Africa ( → SSA (; bare Canada → NA-Canada; international / lowercase (global…) → Global; (Global South — …) → Global-South (…); Belt-and-Road partner states → multi-region; the NA-Asia typo → East-Asia; Salinas Valley California → NA-US with detail; trailing "; national" folded into parentheses on the China policy units. The chile-canada cross-border value keeps both segments (LATAM; NA-Canada).

**Validation rule** (implemented in `scripts/validate_frontmatter.py` from v6): the leading token of each top-level segment must be a controlled prefix, or the value must take the `(cross-cutting — …)` form. Continuation clauses after the first parenthetical are free text and are not validated.

## 2. Claim-type: interim grammar (pending v6 unit-kind)

The v5 vocabulary (example | claim | statistic | framework) described the corpus of July 2026. By November 2026 practice had grown a de-facto composite grammar of ~110 distinct values, and the audit found it is *informative, not noise*: units legitimately carry a primary epistemic type plus a secondary type plus qualifiers — e.g. `framework (the regulation and its amended timeline) + example (named machine classes)`.

v5.1 records the grammar without mass-rewriting values:

```
claim-type: PRIMARY (qualifier) [+ SECONDARY (qualifier)]
```

Recognized primaries in current use: **example, claim, statistic, framework, fact, deployment, programme, pattern** (including the pattern-observation forms: cluster-pattern-observation, critical-voice-pattern, ecosystem-pattern-observation, pattern-institutional-convening).

The kind-flavoured primaries (deployment, programme, pattern, institutional-anchor) overlap with what v6's `unit-kind` tag expresses structurally. Once unit-kind is present, claim-type should migrate back toward the four epistemic primaries (example / claim / statistic / framework) plus fact for maintained trackers — **at refresh cadence, unit by unit, not in a bulk rewrite** (the values carry sourced qualifiers worth keeping until the unit is next opened).

## 3. Cross-cutting marker: canonical form

`(cross-cutting — reason)` is the canonical marker for axis fields that a unit legitimately spans (107 units in sector-position, 100 in technique class, 41 in purpose as of the audit). The 2026-11-15 audit verified the form is used consistently (em-dash separator, parenthesised, reason given); no normalization was required. The marker is machine-detectable, so "cross-cutting" units remain queryable as a class rather than falling out of axis queries silently.

## 4. What v5.1 deliberately did not do

- No new tags (governance-level and unit-kind are v6).
- No rewrite of composite claim-type values (interim grammar recorded instead; migration at refresh cadence).
- No change to the three primary axes or the maturity dimensions (the audit found them sound; coverage of the maturity tags is a separate completion question, tracked in ROADMAP).
- No validation enforcement (the validator ships with v6; until then this document is the convention).

## 5. Audit method (for reproducibility)

Region values: extracted from unit frontmatter, split on top-level commas/semicolons outside parentheses, leading token of each segment counted against the controlled list; all 249 units pass after the normalizations above (two multi-region comma lists validate per segment). Claim-type: full distinct-value enumeration (108 example, 21 framework, 18 claim, 5 statistic, plus ~70 composite/variant values). Cross-cutting: marker-form frequency check. Scripts were one-shot migration tools run 2026-11-15; the permanent validator is `scripts/validate_frontmatter.py` (v6).
